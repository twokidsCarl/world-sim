# world-sim: the structure of a simulation, a map of the field, and the idea pool

中文版：[IDEAS.md](IDEAS.md)

A comparison of the world-sim subprojects, the general structure of a simulation drawn from them, and a growing pool of ideas written in the style of the original briefs.

This file holds two kinds of content. **The idea pool, the kernel table and the coverage table** (the three blocks fenced by comment markers in sections 6, 7 and 8) are generated by [`idea-loom/`](idea-loom) from its event log and must not be edited by hand: change ideas in the idea-loom UI, then press "sync to the repository". The idea texts are translated from the Chinese by a model; the Chinese is the original. Everything else is hand-written analysis.

## 1. Starting point: what the first four projects were

This section and the next two are a snapshot from the early hours of 2026-10-11, when the pool began. They show where the later structure was drawn from. The projects have all moved on a long way since, and limn and idea-loom have joined them; for the present state, see each project's own README and the ladder table in the root README.

| | Core of the original brief | What it actually was | Unit × count | Axis of iteration | Rules | Maturity |
|---|---|---|---|---|---|---|
| **mindloop** | Two people guessing each other, "I know that you know", games and infinite recursion | A level-k recursive game solver, 25 cases from literature, history and game theory, and a web page | 2 people | **Depth of reasoning** 0..12 (no time) | Closed-form equations (soft best response, Bayes), no randomness | Complete, with tests and UI |
| **polis** | A parallel society: decisions, spreading, mental models; observable, open to intervention and projection | Only a data contract and one scenario, a run on a small-town bank | ~1000 people (12 protagonists plus a synthetic population) | 96 hourly ticks | Seeded stochastic agent-based model (designed, engine not written) | Skeleton |
| **strata** | Start from the most basic laws; more is different; emergence level by level | 2D Lennard-Jones molecular dynamics, the micro level only | 1600 particles | Fixed-dt integration | Physical equations (velocity Verlet) | Micro level usable; upper levels and GPU not written |
| **soma** | A 3D simulated human, anatomically real, for surgical training, physically real, able to feel pain | A static 3D anatomy atlas and an offline data pipeline (BodyParts3D, 2.2 GB) | 2220 anatomical parts | None (view state only) | Classification and geometry heuristics | Atlas usable; no physics, surgery or pain yet |

## 2. What they share

1. **Contract first**: every project begins with a data contract (`model.py` / `anatomy/types.ts`) that the engine writes and the UI reads.
2. **Content apart from mechanism**: mindloop's `cases/*.yaml` versus `recursion.py`; polis's `scenarios/` versus the engine; soma's data pipeline versus the viewer.
3. **Numbers are deterministic; the language model only narrates**: every number comes from a deterministic or seeded kernel. The model writes monologues or annotates input, always with a template fallback. None of the four lets a model drive the state.
4. **A real anchor**: mindloop reproduces the ending of each source story (`canonical`), strata tests conservation laws, soma aligns with the FMA ontology, polis plans to align with real data.
5. **A pure kernel and a thin UI**; tests target the kernel and check invariants, not snapshots.
6. **People have names and stories**: the two projects about people use named characters with sources, not abstract agents.
7. **Intervention means changing parameters and recomputing**, not live control; polis goes further and designs "branch from a given tick".
8. Shown in the browser, Chinese first, one toolchain (Python: pydantic + typer + fastapi; TS: bun + vite + react).

## 3. How they differ (the dimensions that can vary)

- **Scale**: 2 people → a society of a thousand → a thousand particles → one body of a thousand parts.
- **Axis of iteration**: time ticks / continuous dt / depth of reasoning / no axis. mindloop shows that what iterates need not be time.
- **Kind of rule**: closed-form solution / stochastic agent-based model / differential equations / pure structure.
- **Weight of input**: hard-coded constants (strata) → YAML cases → Python scenarios → 2.2 GB of external data.
- **What is validated against**: the ending of a story / physical invariants / ontological consistency / nothing yet.
- **Gap between vision and reality**: soma lacks dynamics (the largest gap), strata lacks the upper levels, polis lacks an engine. **Of the four, only strata and (as designed) polis are simulations that evolve in time.**

## 4. The general structure of a simulation (seven slots)

Any idea that fills these seven slots is a project ready to start:

1. **Unit**: the smallest thing (particle, cell, organ, person, belief, message, firm).
2. **State**: what each unit carries (position and velocity / belief and fear / a tower of reasoning).
3. **Relations or space**: continuous space, a grid, a social graph, a hierarchy, none.
4. **Axis of iteration**: time, depth, generations, levels of scale.
5. **Rules**: who wrote them — physical law, game-theoretic best response, heuristics, something learned.
6. **Anchor**: what it is calibrated against — conservation laws, data from the literature, the ending of a classic text, a real dataset.
7. **Observation and intervention**: which macroscopic quantities to watch, which knobs can be turned, whether a run can be branched and replayed.

The original briefs have a stable shape, and new ideas are written to it:

> **An object** (I want to simulate…) + **a hook with depth** (pain / infinite regress / more is different / a parallel society) + **a demand for realism** (medically real, physically real, search the literature, align with data, draw on fiction) + **a use** (training, experiment, intervention, building tasks) + **presentation** (a beautiful UI, replay) + **adjustable base assumptions**

## 5. The frame: one trunk, five threads, several verticals, two branches

### The trunk: a ladder of scales

The existing projects line up: strata (particles) → Goodsell (molecules and cells) → soma (the body) → mindloop (two people) → polis (society). Taken together world-sim is doing one thing: **simulating upward from physical law, level by level, all the way to civilisation**. Every idea hangs on some rung of this ladder.

| Level | Unit | What first appears here | Existing project |
|---|---|---|---|
| L1 Matter | particles | temperature, pressure, phase transitions | strata |
| L2 Molecules and cells | molecules | structure, catalysis, order within crowding | (Goodsell) |
| L3 Tissues and organs | cells | form, rhythm, defence | — |
| L4 The body | organs | a living whole, pain | soma |
| L5 One person | thoughts, habits | self, desire, choice | — |
| L6 Two people | people | mutual guessing, trust, bargaining | mindloop |
| L7 A small group | people | alliances, secrets, teaching and learning | — |
| L8 Society | crowds | markets, rumours, money, cities | polis |
| L9 Civilisation | societies | language, institutions, the lifespan of ideas | — |
| L10 Life and the planet | species, spheres | succession, co-evolution, climate | — |

### Threads: one mechanism running through many levels

Each thread is the same mechanism as it looks on different levels. Ideas written along a thread yield kernels that can borrow from one another.

- **A Propagation**: something passes from one unit to the next. A wave in heart muscle → a virus between cells → a rumour in a crowd → an idea across generations
- **B Criticality and collapse**: nothing happens for a long time, then everything gives way at once. Phase transition → sandpile → a fibrillating heart → a bank run → the fall of a dynasty
- **C Depth of mutual guessing**: "I know that you know." Two people → a negotiation → three people → a web of lies → money that I accept because everyone accepts it
- **D Memory**: how the past stays in the present. Immune memory → neural memory → grudges and forgiveness → copying and misreading
- **E Interfaces between levels**: how a crowd on one level becomes a single thing on the next. Particles → fluid, cells → body, neurons → thought, exchange → money

### Verticals: one event through every level

A third kind besides the trunk and the threads: take one concrete event and follow it from the lowest level to the highest, or from the highest down to the lowest, or round in a loop back to where it began; or the other way, fix the scale and stretch time. Each level gets only its simplest version. What is tested is whether the levels connect.

### Branches: two directions off the ladder

Everything on the trunk grew naturally in this universe. Two kinds of thing do not sit on it; each gets a branch with a small ladder of its own.

- **造 Made things**: the rules were not discovered but written down by people. Parts → machines → systems → machines that learn. It leaves the trunk after L8: society makes it, and it changes society in return.
- **规 Worlds of pure rules**: do not start from the laws of this universe; search among all possible simple rules. The whole space of rules → what grows inside rules → what lies underneath rules. It joins the trunk before L1: strata climbs upward from known laws, while this branch asks what else the laws themselves could have been.

The threads apply on the branches as well.

### L1 Matter (existing: strata)

**1.1 Going up one level** (E)
Continuing from strata: right now there are only particles. I want to see a clump of particles as a small piece of fluid, and then the fluid as a vortex.
At each level up, what is lost, what is kept, and can the rules of the upper level be calculated from the level below?
Look up coarse-graining and renormalisation methods in physics. Show the levels side by side. Change one constant at the bottom and see which level changes first and which doesn't care at all.

**1.2 A sandpile** (B)
I want to simulate sand falling one grain at a time. Most of the time nothing happens, but now and then one grain sets off an avalanche across the whole pile. Nobody tuned any parameter. The system walks itself to the critical point.
Are earthquakes, wildfires, power outages and traffic jams the same kind of thing? Look up this theory, and also real sandpile experiments and the criticisms of it. Compare with real disaster statistics.

**1.3 A single spark** (A, B)
A single spark lands on a stretch of something flammable. Sometimes it dies out on its own. Sometimes it burns into a wide fire.
I want to simulate how heat passes to the neighbouring spot, how that spot catches, and how the flame front moves forward.
Look up the theory of combustion and reaction-diffusion. Later the same core can be used for forest fires, electrical waves in heart muscle, and rumours in a crowd.

**1.4 A snowflake** (E)
A water molecule only knows whether there are other water molecules next to it. Yet a snowflake has six almost identical arms.
I want to simulate a crystal growing from a single seed, to see where the symmetry comes from and why no two are alike.
Look up crystal growth models, and find microphotographs and classification charts of snowflakes to compare with. Temperature and humidity can be changed, to see which kind grows.

**1.5 A metal that remembers being bent** (D)
Bend a piece of wire and straighten it, and it looks the same as before, but it remembers. After how many bends will it break?
I want to simulate how unseen damage inside the material builds up bit by bit, and how past stress is kept in the present structure.
Look up microscopic models of material fatigue and plasticity, and match them to real fatigue test data. Build it up from the particles of strata.

**1.6 A cloud of gas collapsing into a star** (B, D, E)
The particles in strata only push and pull at short range. I want to add gravity: it is weak, but it reaches far, and it only pulls, never pushes.
A cold, thin cloud of gas pulls itself together, and at some moment it gets hot enough to ignite. The leftover dust and rubble circle around it, collide into larger bodies, and in the end a few planets are left, each on its own orbit.
Look up the physics and numerical methods of star and planet formation, and match them to the observed distribution of stellar masses and the statistics of planetary systems. The constants at the bottom can be changed: if gravity is a bit stronger or weaker, is there still a star, and are the planets still arranged this way?

### L2 Molecules and cells (existing: limn)

**2.1 One second inside a cell** (E)
Continuing from Goodsell: what he draws is a still picture, and I want to make it move.
The cell is so crowded there is no empty space, and every molecule is bumping about at random, yet the reactions still happen exactly.
Sizes, numbers and speeds all need real figures from the literature. The look stays true to his style, and any frame, paused, is a scientifically correct illustration.

**2.2 The first molecule that copied itself** (E)
A pot of lifeless chemical soup. I want to simulate how a certain set of molecules starts to catalyse each other, until something appears that can make a copy of itself.
Starting from the particles of strata: when does "chemistry" become "chemistry that is inherited"?
Look up the different schools of hypotheses and experiments on the origin of life, and make the underlying assumptions of each school switchable.

**2.3 The life of a virus** (A, C, E)
A virus is a thousand times smaller than a cell and can do nothing on its own. It has to trick the door open, slip inside, and hijack the machinery in there to make parts for it. The cell has locks and alarms, and if all else fails it kills itself.
Once the parts are made, nobody directs them. Hundreds of identical proteins bump around in the water and assemble themselves into a complete shell, which then goes out to find the next cell.
I want to simulate this whole loop: who has the upper hand at each step of the attack and defence, how the shell gets assembled correctly, and under what conditions it gets assembled wrongly. Look up the full infection cycle of one of the best-studied viruses, and take the timing, numbers and part shapes from real measurements. The look follows Goodsell's style, and on top of it connects the immune war of 3.3.

**2.4 A minimal cell** (E)
I want to simulate the simplest living cell: it eats, makes parts, grows, and divides itself into two.
Take away any one of these and it is no longer alive.
Look up research on minimal genomes and whole-cell models, and take the parts list from the simplest real organism. Genes can be switched off one by one, to see when it dies.

**2.5 How a cell remembers who it is** (D)
Every cell in the body has the same genes, yet a liver cell divides into more liver cells.
I want to simulate how a cell writes down "what I am" and passes it to its descendants, and in what situations it forgets, changing back or turning into cancer.
Look up models of gene regulatory networks and cell fate, and find real reprogramming experiments to compare with.

**2.6 Machines inside the cell** (A, E)
There are molecules in the cell that do work. One has two "feet" and walks step by step along a filament, dragging cargo on its back. Another crawls along a chain, and for every three letters it reads it adds one part, and finally releases something that folds itself up.
They are surrounded by water molecules bumping around at random, yet they manage to work in one direction. I want to simulate how they turn random bumping into work, and what happens when something goes wrong.
Look up physical models of molecular motors and translation, and match step size, speed and error rate to single-molecule measurements. The look follows Goodsell's style and continues from 2.1.

**2.9 A misfolded protein** (A, B)
One protein has folded into the wrong shape. It meets a normal one and bends that one too.
For a long time nothing shows, and then suddenly it is everywhere. I want to simulate how this "bad shape" spreads from molecule to molecule, and why it takes so long to break out.
Look up the kinetics studies on protein misfolding and aggregation, and match the aggregation curves measured in test tubes. Use Goodsell's aesthetic for the visuals.

### L3 Tissues and organs

**3.1 From one cell to a body** (E)
I want to simulate embryonic development. One cell divides, and the cells talk to each other through concentrations and decide for themselves what to become.
Each cell only looks at its surroundings, so who decides the shape of the whole?
Look up the mathematical models in developmental biology, find a simple organism that has been fully traced to compare against, and recreate the classic experiments from history (cutting, transplanting) as scenes.

**3.2 A heart** (A, B)
I want to build a physically realistic heart. The electrical signal spreads, the heart muscle contracts, and blood flows out.
I want to see how a heart that is beating well suddenly turns into a chaotic quiver.
Start from a single heart muscle cell. Look up the mathematical models of heart muscle, and calibrate with real ECG data. It is for medical students, and they can create lesions themselves.

**3.3 An immune war** (A, D)
I want to simulate an infection: a virus enters the body, and the immune system recognises it, mobilises, overreacts and leaves a memory.
Why, with the same virus, do some people recover in three days while others die from their own immune system?
Start from the rules of a single cell. Look up the immunology literature, match real disease-course data, and find in first-hand accounts of a plague one person's path from falling ill to the outcome.

**3.4 A thought** (D, E)
Start from one neuron. All it does is fire once it has built up enough.
I want to simulate how rhythm, memory and choice appear after a few thousand of them are connected.
Look up computational neuroscience and find the simplest rules that are still true to life. Find neural wiring diagrams that have been fully mapped, starting from the smallest organism. I need to see both the single cells and the waves of the whole at the same time.

**3.6 A tree lifting water** (E)
A tree thirty metres tall has no heart and no pump, yet every day it moves hundreds of kilograms of water from the roots to the leaves.
I want to simulate how the water goes up: evaporation at the leaves, the water columns in the thin tubes, the uptake by the roots, and where the columns break in a drought and how the tree saves itself.
Look up the models of plant hydraulics and match sap flow measurements of real trees. I can change the species and the weather and see which one dies of thirst first.

**3.7 Another world in the belly** (B, C)
Hundreds of kinds of bacteria live in a person's gut, and they outnumber the person's own cells. They compete for food, feed each other and poison each other.
I want to simulate how this ecosystem stays stable, how one course of antibiotics throws it into disorder, and whether afterwards it returns to what it was or becomes something different.
Look up the ecological models of the gut microbiome and match real microbiome time-series data. Connect the body above it and the antibiotic grain from 纵 6 below it.

### L4 The body (existing: soma)

**4.1 A surgery**
Continuing from soma: I want to simulate a real surgery, from the first cut to the last stitch.
Tissue has mechanics, cutting causes bleeding, and the patient has vital signs and pain responses. Mistakes must have real consequences.
Pick only one, the most standard surgery. Build it from the step-by-step descriptions in surgical textbooks, and find real surgery videos and intraoperative data to match. It can be replayed for review.

**4.2 A day in the body** (A, D)
Continuing from soma: let this body live through one day. Eat a meal, go for a run, sleep a night.
No organ is in charge. When sugar enters the blood, how do the organs divide the work of storing or burning it? Once running starts, how do heart rate, breathing and body temperature keep up, and which one gives out first? At night, how do the brain, hormones and body temperature take turns shifting gears, and why does one night without sleep take several days to pay back?
Look up the physiology models of metabolism, exercise and sleep regulation, and match real continuous glucose, exercise stress test and overnight sleep recordings. I can change the meal, change the altitude, cross time zones, or swap in a body with diabetes.

**4.3 Ageing** (B, D)
I want to simulate eighty years of a body. Every organ gets a little worse and gets a little repaired each day.
I want to know whether ageing is everything slowly wearing out together, or one place failing first and dragging the others down.
Look up the various theories of ageing and match real population lifespan and disease data. I can intervene: eat less, exercise, replace an organ.

**4.5 A wound** (A, D)
Continuing from soma: the skin is cut open, and then come three weeks.
Stopping the bleeding, inflammation, growing new tissue, leaving a scar. When does each kind of cell arrive and when does it leave, and who is calling them?
Look up the biology and models of wound healing, and find continuous photos of real healing to compare against. I can try things: stitched or not, infected, and why the wounds of people with diabetes heal badly.

**4.6 A hand touching something** (A)
Continuing from soma: with eyes closed, a finger touches something and knows whether it is rough or smooth, cold or hot, and whether it could hurt.
I want to simulate how the receptors in the skin turn deformation and temperature into a stream of signals, how the signals travel all the way up, and at which stop they become "pain".
Look up the neurophysiology of touch and pain, and match real nerve recordings. This is the part of soma's original idea about "having a feeling of pain".

**4.7 Seeing** (E)
Light enters the eye as nothing but a scatter of bright and dark points. What a person sees is a face, or a ball flying at them.
I want to simulate the first few stops, starting at the retina: what each stop throws away, what it pulls out, and at which stop the illusions arise.
Look up computational models of the visual pathway, and use classic visual illusions as the test questions: the simulated eye should be fooled the way a person is.

**4.8 The first breath and the last breath** (A, B)
Continuing soma: the start and the end of a body are both a chain of switches within a few minutes.
Birth: a body that lived nine months in water on an umbilical cord has to switch to breathing on its own. The lungs open for the first time, the blood is rerouted, and a door in the heart closes. Death: the body does not stop all at once. The heart stops, the brain has a few more minutes, and one system fails and drags down the next.
I want to simulate every step in these two stretches, what happens if a step comes late, and up to which step a person can still be saved. Look up perinatal physiology and critical-care resuscitation research, and match real newborn and end-of-life monitoring data. Interventions should be possible: compressions, defibrillation, cooling.

### L5 One person

**5.1 Addiction** (D)
I want to simulate how a person becomes addicted. At first it is liking, then wanting, and in the end having to.
I want to see on which day "liking" and "wanting" come apart.
Look up the neuroscience models of addiction, every school there is. Calibrate against real trajectories from memoirs and novels written by addicts. It should be possible to experiment: when does pulling someone back help.

**5.2 How a body becomes a person** (E)
Continuing soma: the body is there, but there is no "person" in it yet.
I want to simulate how bodily signals such as hunger, pain, tiredness and heartbeat turn into emotions, desires and the sense of "I".
Look up neuroscience theories of interoception and emotion. The same bodily state, in different situations, gets felt as different things.

**5.3 One person's breakdown** (B)
A person carries a little more each day and seems fine the whole time, then one day can't hold up any longer.
I want to simulate how stress, sleep, energy and mood drag on each other, and whether there are warning signs before the collapse.
Look up research in psychology and psychiatry, and calibrate against real trajectories from memoirs and novels. It should be possible to experiment: at which moment would a rest have prevented the collapse.

**5.4 A decision** (B)
A person faces two roads, hesitates for a long time, then picks one.
I want to simulate what happens during the hesitation: how evidence builds up, how emotion gets involved, and why sometimes it drags on and the choice at the end is arbitrary. And after choosing, how he talks himself into believing he chose right.
Look up cognitive models of decision-making and research on regret, match real choice-experiment data, and find people's own accounts from before and after big decisions in diaries and letters.

**5.5 A lifetime** (D)
Put the same child into a different home or a different era. Would they grow into a different person?
I want to simulate eighty years of one person: how temperament, habits and chance shape each other, and which early events keep working on them later.
Look up longitudinal studies that span decades, and calibrate against complete life trajectories from biographies and oral histories. It should be possible to rerun the same person many times and see which outcomes are common.

**5.6 An idea** (D, E)
A person thinks for a long time and gets nowhere, goes to take a shower, and it comes to them on its own.
I want to simulate how a new idea is put together from old things: how two unrelated thoughts meet, and why staring at the problem keeps them from meeting.
Look up cognitive research on creativity and insight, and find out from the memoirs of scientists, writers and inventors what happened before "that moment". Continue the thought from 3.4.

**5.7 A dream** (D)
After a person falls asleep, the brain does not stop. It digs up the day's events, mixes them with things from long ago, and stages a play with no beginning or end.
I want to simulate how memories are replayed, recombined, kept or dropped over one night, and whether dreams are a by-product of this process or the process itself.
Look up research on memory consolidation during sleep, and compare against large corpora of dream reports. Continue from the sleeping stretch in 4.2, a day in the body.

**5.8 Bargaining with tomorrow's self** (C)
Tonight's me wants to play a bit longer, and tomorrow morning's me has to get up early. Tonight's me knows tomorrow's me will regret it, and tomorrow's me knows tonight's me can't be trusted.
I want to split one person into several selves at different moments and simulate how they scheme against each other and guard against each other: setting an alarm, making a vow, locking the phone away.
Look up research on procrastination and self-control, and match real behavioural experiment data. The two people in mindloop become the present and the future of the same person.

**5.9 The thing that won't stop** (A, B)
A harmless remark in the daytime grows bigger and bigger in the head after lying down at night.
I want to simulate how one thought spreads through a person's mind: which other thoughts it calls up, how those call it back, and when it becomes a loop with no way out.
Look up cognitive models of rumination and attention, and find records of such nights in diaries and personal accounts. It should be possible to experiment: what breaks the loop.

### L6 Two people (existing: mindloop)

**6.1 The negotiating table** (C)
Two people negotiate. Each has a bottom line they don't tell the other, and they bluff, probe, and pretend they are about to leave.
I want to simulate the rhythm of concessions, the moment it breaks down, and what happens after "he knows I'm faking".
Look up bargaining in game theory. Find cases in histories, plays and real negotiation records, and each case should be able to reproduce its outcome.

**6.2 How trust is built and how it collapses** (B, C, D)
How two strangers come to trust each other, and whether a relationship can be repaired after a betrayal. There is another ending too: no single day when something big happens, just fewer and fewer words, and some acts of patience turning into keeping score.
I want to simulate testing each other, giving up an advantage, holding grudges, forgiving, and how a relationship slowly cools when no one is paying attention. Which small habit is a warning sign, and at what point can it still be turned back?
Look up research on repeated games and long-term studies that followed couples, and align the model with the predictive signals they found. Use the formation and breakdown of friendships, marriages and partnerships in literature, film and first-person accounts to calibrate.

**6.3 The first time you realise others have minds** (E)
The two people in mindloop start guessing each other from the very beginning. I want to step back one stage: how does a person begin to hold another person in their head?
Simulate a child going from "what others know is what I know" to understanding that others can believe wrong things, can lie, can pretend.
Look up the classic experiments in developmental psychology, treat each experiment as a level, and see at what age the simulated child can pass it.

**6.4 Doctor and patient** (C)
The patient says where it hurts, and the doctor guesses what the illness really is. A patient afraid of being looked down on says too little, and one afraid of being ignored says too much; the doctor knows the patient does this.
I want to simulate how information flows in a single consultation, and at which sentence a misdiagnosis gets planted.
Look up research on doctor–patient communication and diagnostic reasoning, and find cases in real consultation records and doctors' notes. Use it to let medical students practise taking a history.

**6.5 Parent and child** (C, D)
Two people, one who understands everything and one who understands nothing, and the gap changes every year.
I want to simulate twenty years: how the child learns to test boundaries, how the parent decides when to let go, and who first notices that the other is no longer who they used to be.
Look up long-term studies in developmental psychology and attachment, and calibrate with real fathers, mothers, sons and daughters from family letters, memoirs and novels.

**6.6 Human and AI** (C)
Replace one of the two people in mindloop: a person facing an AI.
The person is guessing whether it really understands, the AI is guessing what the person wants to hear, and the person knows it is guessing what they want to hear.
I want to simulate how trust, dependence and doubt grow in this kind of relationship. Look up research on human–computer interaction, and find real conversation records to align with.

**6.7 Interrogation** (C)
Two people, one who wants to know and one who doesn't want to say. One can wait, and the other doesn't know how much the first already knows.
I want to simulate the probing and defending in this conversation: how the questioner pretends to already know, and how the one answering says only what the other already knows. Who shows their hand first.
Look up research on interrogation and questioning, and find cases in courtroom cross-examination records and in face-offs in novels and plays. In mindloop, this is the first time the two people are truly hostile.

**6.8 How two people fall in love** (C, D)
Two people, neither sure what the other is thinking, neither wanting to be the first to say it out loud.
Say it too early and you fear scaring them off; say it too late and you fear missing it. Every sentence leaves a way back, and the other person knows the sentence left a way back. I want to simulate how this testing tightens step by step.
Look up research on how close relationships form, find cases in novels, opera, love letters and diaries, and mark every step forward and every half step back. In mindloop, this is the gentlest kind of mutual guessing.

**6.10 A yawn** (A)
One person yawns, and the other yawns too. After two people talk for a while, their speech rate, word choice and posture become more and more alike.
I want to simulate this kind of contagion between two people that doesn't pass through thought: emotion, rhythm, accent, and what kind of pair can't get in step.
Look up research on interpersonal synchrony and emotional contagion, and align with second-by-second records of real conversations. This is the half between two people that doesn't depend on guessing.

### L7 A small group

**7.1 Three people** (C)
Continuing from mindloop: two people guess each other, and then add one more.
Two can join forces against the third, and the two who joined forces each guard against the other. Who said what to whom, and whether the third person knows.
Find cases in histories, palace dramas and family dramas. I want to see at what level of thinking an alliance flips.

**7.2 The life of a lie** (A, C, D)
I want to simulate what happens after a person tells one lie. To cover it he has to tell more lies, each person who hears it remembers a different version, and he has to remember who knows what.
I want to see at which step the lie collapses, and because of which people meeting each other.
Find cases in novels, plays and court records, and break them down into "who told whom which version, and when".

**7.3 A classroom** (A)
One teacher talks and thirty students listen. Each has different prior knowledge, understands differently, and misunderstands differently.
I want to simulate how knowledge gets passed along, how misunderstandings grow, and how the teacher guesses whether the students understood.
Look up common misconceptions in education research, and align with real classroom records. Use it to try out different ways of teaching.

**7.4 The breakup of a team** (B, C)
A band, a startup team, a research group. At first everyone gets along well, and later it falls apart.
I want to simulate how the division of work, credit and resentment build up, who left in their heart first, and when the others noticed.

**7.5 A family** (C, D)
Four or five people live under one roof for decades. Who handles the money, who cooks, who isn't speaking to whom, what is never mentioned.
I want to simulate how a family's rules and roles get settled, and how they get passed down unchanged into the next generation's families.
Look up research on family systems, and calibrate against real families spanning three generations, drawn from family novels, family letters and oral histories.

**7.6 Twelve strangers** (A, C)
Twelve people who don't know each other are locked in a room and must reach one unanimous conclusion.
I want to simulate how the first round of stated positions sets the tone, under what conditions the minority can turn it around, and who hasn't really thought it through and is just following along.
Look up research on juries and group decision-making, and match it against real deliberation records and experimental data. I can change one person's seat or the way of voting and run it again.

**7.7 A table of cards** (C)
Four people play cards. Nobody can see anyone else's hand, but every card played gives a little away.
I want to simulate how each person's guesses about the other three hands change during a game, when bluffing works, and at which level veterans and beginners differ.
Look up solution methods for imperfect-information games, and match them against real game records. This is the four-player, multi-round version of mindloop, with luck.

**7.8 A football match** (A, E)
Eleven people against eleven, one ball. Nobody can direct every kick, yet the formation holds itself and chances appear on their own.
I want to simulate how each player decides by looking only at the few people near them, and how the whole team's attack and defence grow out of that.
Look up modelling research on team sports, and match it against real player-tracking data from matches. I can change the formation, swap one player, or take one player away.

### L8 Society (existing: polis)

**8.1 How money appears** (C, E)
A group of people can only barter. I want to simulate how one thing slowly becomes the "money" that everyone accepts.
Then loans, interest and banks grow on top of it layer by layer, and finally connect to the bank run in polis.
Look up economics models of the origin of money, and also the objections to them from anthropology and history. I want both sides. Find one well-documented real case to reproduce.

**8.2 The attention economy** (A)
A group of people post content and view content, and a recommendation algorithm decides who sees what.
I want to know whether polarisation and echo chambers are chosen by people themselves or made by the algorithm.
Look up the communication research whose conclusions contradict each other, and match it against real communication data. The recommendation algorithm is an underlying assumption that can be swapped, and each swap gives a different society.

**8.3 A city for a day** (A)
I want to simulate a city for 24 hours: people wake up, commute, work, eat and go home.
Each person has only a simple daily schedule, and rush hours, traffic jams and busy commercial districts appear on their own.
Pick a real city, and use real data for the road network, timetables and population. I want a very beautiful map whose time can be dragged.

**8.4 The bullwhip** (A, B)
A supply chain: customers, shops, wholesalers, factories, raw materials. Each link can only see the orders from the next link.
I want to simulate how a small fluctuation in demand gets amplified all the way into big swings at the factory.
Look up supply chain theory and experiments, and pick one or two real shortage events to reproduce.

**8.5 How a society remembers something** (A, D)
Continuing from polis: the bank run is over. Ten years later, fifty years later, how do the people of this county town tell the story?
I want to simulate those who lived through it growing old, the story being told to the next generation, and how the official account and the popular account split apart and rewrite each other.
Look up research on collective memory, and find several oral and written accounts of the same event, decades apart, to compare.

**8.6 Where rules come from** (C, E)
A group of people has no laws and no officials. I want to simulate how they slowly come to have rules of "everyone does it this way", and then people who specialise in looking after the rules.
Queueing, keeping to the right, repaying debts: none of these were laid down by anyone.
Look up theories of social norms and the origin of institutions, and find cases to compare from anthropological field records and real communities without a government.

**8.7 A market** (B, C)
A group of people buy and sell the same thing. Each person is not guessing what it is worth, but guessing what others think it is worth.
I want to simulate how a price comes out of this mutual guessing, how a bubble gets blown up, and at what moment everyone wants to run at once.
Look up multi-agent models of financial markets and laboratory bubble experiments, and pick one or two real bubbles to reproduce. It can connect to the bank run in polis.

**8.8 From a group of people to an organisation** (E)
A few friends do something together. Everyone knows everyone, and everything is settled by talking it over. Once there are enough people, past a certain number, that stops working.
I want to simulate how positions, regulations and levels grow out of this, and from what moment the organisation is still itself even after every person has been replaced.
Look up theories from organisational sociology, and find real growth processes to compare from the early histories of companies, clubs and armies. Continue from the team in 7.4 that didn't fall apart.

**8.9 A riot** (A, B)
Continuing from polis: a crowd gathers on one street. Everyone is angry, and no one wants to be the first to act.
Each person has a number in their head: when I see this many people move, I move too. I want to simulate how that number is spread across the crowd, and how it decides whether the day ends in calm dispersal or in fire.
Look up threshold models of collective behaviour and the empirical studies, and calibrate from the timelines, footage and eyewitness accounts of real events. Interventions are possible: where the police stand, when a message arrives.

**8.10 A village grows into a city** (D, E)
A few households beside a river crossing. A thousand years later, a city of several million people.
I want to simulate where the roads reach, where the markets settle, how rich and poor come to live apart, and why a road laid down casually in the early days is still there today.
Look up models and regularities of urban growth, match them to a real city with maps from several eras, and draw on old maps, local gazetteers and aerial photographs. Continues from the day in 8.3.

**8.11 A trial** (A, C)
Something happened, and no one saw all of it. Each side tells its own version, each witness remembers a little, and in the end someone has to say "what the facts are".
I want to simulate how evidence and accounts are laid out and torn down in court, how the scale in the decider's mind moves, and at which step a wrongful conviction is settled.
Look up research on forensic psychology and reasoning about evidence, and find material in real trial records and in cases that were later overturned. This builds on the twelve strangers in 7.6.

**8.12 An election** (A, C)
Continuing from polis: everyone in the city has to choose one of two or three candidates.
Each person has their own views, also looks at what neighbours think, and also guesses who will win. No one wants to vote for someone who is bound to lose. I want to simulate how public opinion moves in the last few weeks, and how a small event can turn the result around.
Look up research on voting behaviour and opinion dynamics, and match it to a real election with daily polls. The counting rule can be changed, to see whether the same people would elect a different person.

### L9 Civilisation

**9.1 The dynastic cycle** (B)
I want to simulate a dynasty from its founding to its collapse. How land, population, taxes, bureaucracy, army and natural disasters interlock.
I want to know whether the collapse was already decided in the golden age.
Look up theories that explain the rise and fall of dynasties with mathematics, and the historians' criticisms of them. Calibrate from the official histories and historical data, and pick two or three real dynasties to reproduce. It should be possible to run what-ifs: change one policy, and see whether the dynasty lasts a few decades longer or falls sooner.

**9.2 The birth of a language** (D, E)
A group of people with no common language have to work together. I want to simulate how words get agreed on, how grammar appears, and how dialects split.
At the very bottom there is only this: pointing at a thing, making a sound, and whether the guess was right.
Look up models of language evolution, and find records of new languages arising from nothing in the real world to compare against.

**9.3 A thousand years of an idea** (A, D)
An idea is spoken by one person, then written down, misread, rewritten, and put to other uses.
I want to simulate how it changes shape from generation to generation, splits, vanishes, and is rediscovered.
Pick one long-lived story and one philosophical concept, find all their versions, and reproduce the real lineage. Draw it as a tree that keeps growing.

**9.4 A craft is lost** (A, D)
A craft is handed down from master to apprentice. Some things can't be written down and can only be taught hand to hand.
I want to simulate how it was passed on for hundreds of years, and how it broke off within two or three generations.
Look up real cases of loss and recovery in the history of technology, and find craftsmen's oral accounts and records of apprenticeship. Interventions are possible: write it into a book, open a school, skip a generation.

**9.5 Suspicion between two countries** (B, C)
mindloop scaled up to nations: neither country wants war, but each fears the other will strike first.
You build weapons to protect yourself, and to me it looks like you mean to attack me. I know you will see it that way, so I have even more reason to build.
Look up the security dilemma and crisis decision-making research in international relations, find cases in the declassified archives and memoirs of real crises, and reproduce which ones ended in war and which did not.

**9.6 A discovery changes a civilisation** (A, E)
One person discovers something. Sometimes it changes the whole world within a few years, and sometimes it sits for hundreds of years and no one pays attention.
I want to simulate what a discovery has to meet, such as tools, needs and people who can understand it, before it really spreads.
Look up the history of science and research on technology diffusion, find real cases of things discovered more than once, forgotten and then picked up again, and reproduce their timelines.

**9.7 The rise of a faith** (A, D)
At first only a dozen or so believed. Three hundred years later half the world did.
I want to simulate how a faith spreads: who believes first, what keeps people in, why it grows faster when it is suppressed, and how it splits into factions.
Look up the sociology of religion on the growth of early sects, match it to real historical cases with estimated numbers of believers, and find material in church histories, letters and the records of its opponents.

**9.8 A style goes out of date** (A, B)
A way of painting, a kind of music, a way of dressing. It goes from the quirk of a few people to everyone's standard, and then suddenly looks old.
I want to simulate how people want to be like others and also different from them, and how these two forces produce wave after wave of trends.
Look up models of fashion and cultural taste, match them to real data with long records (baby names, popular songs, art schools), and find in art history how each replacement came about.

**9.9 Several societies joined into one civilisation** (A, E)
Several unrelated societies, each with its own language, its own gods, its own money. Mountains and seas lie between them.
I want to simulate how trade routes, intermarriage, war and writing connect them, when they start to count as "one world", and when a famine in one place starts to reach another.
Look up research on long-distance exchange networks in history, match it to archaeological records of how goods and technology spread, and pick one real trade route to reproduce.

**9.10 A kind of game** (C, D)
A kind of board game, a kind of ball game, a kind of card game. Once the rules are set, people start working out how to win, and the ways of winning they work out force the rules to change.
I want to simulate how rules and play chase each other: how a game gets played out and broken, then patched or abandoned.
Look up real games that have long records of play and a history of rule revisions, and match the changes in how they were played. What iterates is generation after generation of players.

**9.11 A war that lasted decades** (B, C)
Both sides thought it would be over in a few months. Decades later it is still going, and no one can say clearly why it started.
I want to simulate how a war becomes unable to stop: who lives off it, why a ceasefire is always just short, and what happens when a generation grows up never having seen peace.
Look up research on how wars last and how they end, and match it to a real long war with a detailed chronicle, drawing on histories, letters and the records of both sides. This follows on from the two countries in 9.5.

### L10 Life and the planet

**10.1 A hundred years of a forest** (B)
Seeds fall, trees compete for sunlight, fire, pests, succession. Each tree knows only the light and water around it.
I want to see how a stretch of bare ground turns into a mature forest.
Look up forest dynamics models and calibrate them with long-term plot data and remote sensing. I can intervene: logging, introducing species, putting fires out or setting them.

**10.2 Two species reshaping each other** (C, D)
Two species, generation after generation, push each other to change. Predator and prey work against each other: faster running, better hiding, and after all that running, are they still where they started? People and wolves, people and wheat move closer: people choose it, it also chooses people, and in the end neither can do without the other.
What I want to simulate is not time but generations: each generation changes only a little, and I want to see what it ends up as, and who really domesticated whom.
Look up theories of coevolution and domestication, with genetic and archaeological evidence, and find a real pair of species with measured records for each case to reproduce. I can freeze one side so it is not allowed to change.

**10.3 The climate of a planet** (B, E)
Start with the simplest accounting: how much energy the sun gives, and how much the planet sends back.
Then add atmosphere, ocean, ice and life, and see at which layer ice ages, monsoons and greenhouse conditions appear.
Look up the levels of climate models, from the simplest to the most complex. Every assumption can be switched off, to see what the world becomes without it.

**10.4 Life rewrote the planet** (B, E)
Join the head and tail of the ladder: a tiny kind of life starts to release a gas, and hundreds of millions of years later the air, rocks and oceans of the whole planet have changed.
I want to simulate how life and a planet shape each other, and the few times life nearly killed itself.
Look up research on the coevolution of atmosphere and life in Earth's history, and match it to the geological record. I can change the starting conditions to those of another planet and run it again.

**10.5 A mass extinction** (A, B)
An ecosystem looks stable. One species is lost, then a whole chain after it.
I want to simulate how extinction travels along the web of "who eats whom, who depends on whom", and which species are the ones whose removal brings everything down.
Look up food web models, and match them to the mass extinctions in the fossil record and to real ecological collapses that have been documented. I can run experiments: which one to save first to do the most good.

**10.6 A shared pasture** (B, C)
A grassland where anyone can graze sheep. Each person gains by adding one more sheep, and if everyone adds one, the grass is gone.
But in real life many such places have been used for hundreds of years without collapsing. I want to simulate how they manage it, and under what conditions they collapse.
Look up theory and field studies on governing common resources, and find real pastures, fisheries and irrigation channels, some that lasted a long time and some that have collapsed, to compare. The grass grows according to an ecological model.

### Verticals: one event through every level

A third kind besides the trunk and the threads: take one concrete event and follow it from the lowest level to the highest, or from the highest down to the lowest, or round in a loop back to where it began; or the other way, fix the scale and stretch time. Each level gets only its simplest version. What is tested is whether the levels connect.

**纵 1 A glass of wine**
A glass of wine goes down. I want to follow it from start to finish: the molecules enter the blood, the liver works on them, the brain starts to slow, the person talks more, a conversation between two people changes in tone, the mood of a whole table changes.
Then further up: why a society regulates alcohol, and how a civilisation's drink came to be.
Each layer is done in its simplest version. What matters is that the inputs of the upper layer really come from the outputs of the lower one. Look up real measurements for each layer to match against.

**纵 2 A fright**
A noise in the dark. Within half a second the body has already changed: heartbeat, breathing, muscles, pupils. Only then comes "I'm afraid".
I want to follow it from the sense receptors to the emotion, to the decision to run or not, and then to one person running in a crowd, and everyone running.
Look up the neural and physiological pathways of fear, and research on crowd panic. The last layer can connect directly to polis.

**纵 3 A plague**
One mutation in one virus. I want to follow it from a cell to a patient, to a household, to a city, to changing the course of a dynasty.
Every layer already has a simulation I want to make: the immune war, doctors and patients, a day in a city, rumours, the dynastic cycle. This one joins them together.
Take data and first-hand writing from the best-documented plague in history, and every layer has to match it.

**纵 4 A government decree**
The first three go from the bottom up. This one goes the other way: the court changes a tax law.
I want to follow it down: what it becomes in the province, what it becomes in the county, and then at one village, at one family's dinner table, and finally in a child's height.
At each level down, how it is understood, how it is carried out, how it gets distorted. I want to look up research on policy implementation and one well-documented reform in history, and find matching records for every level.

**纵 5 A job loss**
This also goes from the top down: a market collapses, a factory closes, a person loses their job.
I want to follow it further down: who in this family starts to go quiet, how this person's sleep, blood pressure and immunity change, and how long before their body starts to have problems.
I want to look up longitudinal studies on the effects of unemployment on health, and align every level with real data. Upward it connects to the market in 8.7, and downward to the collapse in 5.3 and to the body in soma.

**纵 6 One antibiotic pill**
This one goes around in a loop. A person is sick, takes a pill, and the bacteria die.
But a few don't die. I want to follow them: they grow inside this person, pass to the family, enter the hospital, enter the drains and the farms, and decades later return to another patient, and this time the drug doesn't work.
I want to look up research on how resistance evolves and spreads, and align every level with real surveillance data. It should be possible to intervene: prescribe less, finish the full course, ban use on farms.

**纵 7 A river**
This is also a loop. People build a dam on a river so that there will be no more big floods.
The river changes: the silt, the fish, the fields downstream, the shore at the river mouth. Decades later these changes come back to the people: they switch crops, move villages, and in the end argue over whether the dam should be taken down.
I want to look up a real river with long-term hydrological and social records, and draw on local gazetteers, engineering archives and the oral accounts of families along the banks.

**纵 8 The same place**
The earlier vertical lines all move along scale. This one moves along time: pick one point on Earth and stand still.
In one second, air molecules are colliding. In one day, it is light and shadow. In one year, the grass grows and dies back. In a hundred years, several families come and go. In ten thousand years, the river changes course. In a hundred million years, this place was once sea.
I want to build a window where time scale can be dragged smoothly, and every setting is a simulation that is really running. Pick a real place with records at every time scale.

**纵 9 The same second**
The opposite of 纵 8: time stops at one second, and scale is stretched from small to large.
In this second, an ion passes through a gate, a heart beats once, a person makes up their mind, a sentence is spoken, a trade is made, and a species loses one individual.
I want to align the simulations of all the layers to the same second and see whether they are telling the same story. This is a way to test whether the whole ladder is connected.

### Branch 造: made things

From parts to machines that learn. The first few are about how rules written by people grow behaviour nobody wrote; the last few are about made things starting to learn on their own.

**造 1 From one switch to a computer** (E)
A switch can only be on or off. I want to start there and build upward: a few switches make a gate that can decide, a pile of gates make something that can add and something that can remember one digit, and in the end a machine that can run programs.
Each layer uses only the parts built in the layer below. This is the version of strata's "go up one level" in the man-made world, with the difference that here every layer is designed by people.
I want to look up minimal teaching implementations of computer architecture. It should be possible to zoom in from a running program all the way to the flip of one switch.

**造 2 A bridge** (B, D)
A bridge has stood for fifty years. With every vehicle that crosses, it tires a little. Every winter, it rusts a little. No one can see it.
I want to simulate how load is shared between beams and cables, how a small piece of damage changes the forces elsewhere, and in the end which member breaks first and whether the bridge still stands after that.
I want to look up research on structural mechanics and structural health monitoring, and align with a real collapse that has a complete investigation report. It continues from the bent metal in 1.5.

**造 3 A power grid** (A, B)
Thousands of generators, thousands of kilometres apart, have to turn at the same beat, without being off for a moment.
One line trips, the current crowds onto the lines next to it, and those trip too. I want to simulate how a small fault turns into a blackout across half a country within minutes.
I want to look up models of grid stability and cascading failure, and align with a real blackout that has second-by-second records. It should be possible to intervene: where cutting the grid on purpose can save the rest.

**造 4 A data packet** (A, B)
A message is cut into small pieces. Each goes its own way, passes through dozens of machines that don't know each other, and is put back together at the other end.
No one directs the whole. Each machine only knows where to send things for the next hop. I want to simulate how routes are found, what happens when there is a jam, and why sometimes everyone backs off at once and retries at once, and they all jam together.
I want to look up research on network protocols and congestion control, and align with real network traffic records.

**造 5 Ten years of a codebase** (B, D)
A program is very clean when it is first written. Ten years later, hundreds of people have changed it, and no one understands all of it.
I want to simulate how a codebase grows up: how the bit of debt left each time someone takes a shortcut makes the next change slower, which modules become places no one dares touch, and when people decide to tear it down and rewrite.
I want to look up empirical research on software evolution, and align with the full commit history of public codebases. The world-sim repository itself can be used as data later.

**造 6 An accident** (A, B)
Every line of defence has holes. Normally the holes don't line up. One day they happen to line up in a straight line.
I want to simulate how a system with layers of defence ends up in a major accident: a small fault, an ignored alarm, a well-meant mistaken action, and how one link follows another.
I want to look up theory on accidents in complex systems, pick several complete real accident investigation reports, and reproduce them minute by minute. It should be possible to go back to any step and ask: what if something were done differently here?

**造 7 A trained AI** (D, E)
A network that knows nothing looks at many examples and learns.
I want to simulate how "learning" happens: what it learns first and what it learns later, whether it gets better little by little or suddenly clicks at one moment, whether it remembers the pattern or the answers.
Use a network small enough that I can see every number. Look up research on training dynamics and interpretability. I need to see the overall score curve and what one single part inside is doing, at the same time.

**造 8 A crowd of AIs** (C, E)
Following on from 6.6: it is not one person with one AI, but many AIs dealing with each other, with people watching from the side.
Will they form a division of labour, jargon and tacit understanding on their own, or even band together? I want to simulate what grows in such a group, and see which parts look like human society and which parts look nothing like it.
Look up research on multi-agent systems, and line up with existing records of experiments where multiple models interact. Swap mindloop and polis's participants for non-human ones.

### Branch 规: worlds of pure rules

From the whole space of rules, to what grows inside rules, to what lies underneath rules. This branch has no real-world data to align with; it aligns with facts already proven in mathematics, and with the shapes of the phenomena on the trunk.

**规 1 All the possible rules** (B, E)
A row of cells, each either black or white. The colour at the next moment depends only on the cell itself and its two neighbours, left and right. There are only a little over two hundred such rules.
I want to run all of them and look at them side by side: some die at once, some repeat forever, some turn into a mess, and a few grow something complex that I can't easily describe. Then I want to treat each rule as a point on a map, and see whether the interesting ones all crowd along the border between dead and messy.
Look up the research on classifying cellular automata, the "edge of chaos" idea and the criticism of it, and find a way for the machine to tell what is "interesting" by itself. This pushes strata's "the underlying assumptions can be changed" as far as it goes.

**规 2 Creatures in the grid** (D, E)
A two-dimensional grid, with a rule of only two or three sentences. Yet inside it there are things that walk, things that shoot out other things, and things that make a copy of themselves.
I want to simulate the "biology" of this world: what stable things exist, what happens when they collide, and whether a computer can be built inside this world.
Look up the structures already discovered under this kind of rule and the conclusions already proved, and turn them into a catalogue I can click open and browse.

**规 4 Smoothing out the grid** (E)
The grid is square and time moves in jumps, so everything that grows has sharp corners.
Replace the grid with continuous space, black and white with shades, and jumps with slow flow. With the same kind of simple rule, will something more like a living thing grow: round, soft, able to swim?
Look up research on continuous cellular automata. Make every parameter of the rule draggable, and see in which range the creatures can stay alive.

**规 5 Space also grows** (E)
The earlier ones all gave a grid first. This one doesn't even give a grid: there are only some points and links, and a rule that says "when you see this kind of connection, change it into that kind."
Keep changing, and see whether this network grows by itself into something like a one-dimensional line, a two-dimensional surface, or three-dimensional space.
Look up research on generating spatial structure with rewriting rules, and how physicists judge this path. Look up both sides.

**规 6 Is there physics in the rules** (A, E)
Back to the main line. In these artificial rule worlds, is there anything that moves stably like a particle, is there any quantity that never changes, and is there a fastest speed at which a message can travel?
I want to look in the rule worlds for what is on strata's level: conservation, symmetry, causality. If I find them, it shows these are not things that only our universe has.
Look up research on reversible cellular automata and lattice gases. strata's testing methods can be taken over directly.

**规 7 A pot of random programs** (B, E)
A large pile of randomly generated small programs is put together, and they can read and rewrite each other.
At first it is all gibberish. If it runs long enough, will a program appear that can copy itself, and then fill the whole pot of soup?
This is the pure-rules version of 2.2 "the first molecule that copies itself." Look up experiments in artificial life on self-replication appearing spontaneously, reproduce one, then change the underlying instruction set and see whether the conclusion still holds.

**规 8 How far a few axioms can go** (D, E)
Start from a few self-evident statements, and at each step allow only the stated ways of deriving. Everywhere that can be reached is the world of this set of axioms.
I want to draw this world: which theorems are close to the start, which need a long detour, and after one axiom is swapped out, which region collapses and which stays.
Pick an axiom system small enough that part of it can be exhaustively explored. Look up research on automated theorem proving and on the structure of formalised mathematics libraries.

## 9. A sketch: how a hundred simulations might one day connect

**Most of this section is still a sketch.** The present decision is to build more subprojects, each on its own, and to come back to unification once enough has been built. What follows records directions worth considering then.

Two pieces now exist in a minimal form: each project's "card" (`sim.json`, which so far only declares how it is hosted and which cards it offers, without the "hands upward / needs from below" fields), and the single entry point within "one shell" — idea-loom hosts every simulation and its play page lays the cards out in one column. The contract is in the root `CLAUDE.md` under "the single entry point and the embed contract"; that section does place requirements on the projects, while the rest of this one still does not.

The starting point is the clustering in section 7: a hundred ideas use only a dozen or so kinds of computation. So the end state should not be a hundred unrelated projects but a dozen engines, one shared record format, one shell, and a hundred pieces of "content". mindloop is already an early form of this: one engine and a couple of dozen case files.

### Structure: a "card" for every simulation

Each project declares its place on the ladder: which level, which threads, which kernel, what real data it aligns with. Two fields matter most:

- **what it hands upward** (the particle level hands up temperature and viscosity; the heart hands up how much blood it pumps per minute)
- **what it needs from below** as parameters

These two fields are the interfaces between levels, and the verticals cannot run without them. The ladder table and a navigation map could be generated from the cards.

### Engine: unify the run record first, not the code

Some projects are in Python and some in TypeScript, and forcing shared code would be costly. What can be shared is the output: every run writes a record in one format — parameters and seed, the observables at each step, the stream of events, whether the run can be branched from a given step. The polis data contract already designs all of this and could be the starting point.

Kernel code should be factored out only when a second idea needs the same kernel, not abstracted in advance. The first trial could be "thresholds and cascades": the sandpile and the riot as two pieces of content on one kernel. If that works, the road is open.

### UI: one shell, with each project supplying only the stage

The shell takes care of what is the same in every simulation:

- **Ladder navigation**: zoom in or out from one level to the next
- **Timeline**: play, drag, replay
- **Curves of observables and the event stream**: read straight from the run record
- **A panel for parameters and interventions**, with a side-by-side comparison of two runs after a branch

Each project supplies only the picture in the middle. One visual standard for all.

### The order, when the time comes

Cards → run record format → the shell's map and navigation → the first shared kernel.

### When to come back to this

There is no fixed date. Signs to watch for:

- two projects have each written almost the same kernel
- the first vertical is attempted and two levels turn out not to connect
- there are so many UIs that each one has to be learned afresh
